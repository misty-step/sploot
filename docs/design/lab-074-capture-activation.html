Structure. The empty grid is replaced by a two-lane rig: left lane is an example pile of doodle MemeCells with one lime match — the product action demonstrated statically (serves 053's aha routing). Right lane is a console-styled "capture surfaces" panel: one bordered row per surface with an LED (wired / not wired) and a one-tap action. Rows are device-aware: desktop leads with the extension (store link), Android leads with the PWA install prompt (share sheet unlocks with install), iOS leads with the shortcut (routes to the token minting anchor). Paste/drag row is pre-lit — something already works.

Why it can win. Activation is in the first viewport, unmissable, but framed as the machine's own setup panel — exposed database, not onboarding chrome. Satisfies the DESIGN.md empty-state rule literally. Both cards' criteria in one surface.

Risk. Densest option; must stay legible on a 375px viewport (lanes stack).

Structure. A numbered work-ticket card (checklist + progress sticker) sits where the grid would be; each step has a one-tap action; completing steps checks them off across sessions.

Why rejected. Gamified onboarding checklists are the most SaaS-coded pattern in the candidate set — DESIGN.md bans "corporate AI-search sameness" and the voice is deadpan, not achievement-driven. Also serializes the surfaces into steps when the real decision is per-device (an iPhone user should never see "install the chrome extension" as step 1). No example pile, so it fails the empty-state grammar rule on its own.

Structure. The machinery status bar gains a capture: 0 surfaces wired cell in warning orange; tapping it slides up (animate-sploot-slide-up) a capture panel with the per-surface rows. Empty grid center stays a minimal drop zone.

Structure. Coach-mark stickers pinned to the existing chrome: a magenta hint on the mobile command dock's upload slot, a beacon on the desktop toolbar pointing at an "add capture" menu. Grid untouched.

Structure. The empty state is a live demo: the search console auto-types a query, the doodle pile reshuffles, the match ring locks — then the CTA row pitches the capture surfaces. The full landing-hero mechanic, replayed in-app.

Why rejected (as scoped here). Highest aha-density and the natural home for sploot-053's mechanism — but ambient auto-typing animation on an idle surface violates DESIGN.md motion rules ("do not animate idle data"), and the capture CTAs become a footer to a demo rather than the subject. 053 should decide the live-demo question; 074 takes the static match tableau (option 1's left lane) which delivers the same story without idle motion.

decision — option 01: two-lane capture rig

Rationale. Only options 1 and 3 put per-surface activation in the 0-asset first viewport (criterion 1); of those, only 1 gives every surface its own one-tap row with wired/unwired state (criterion 3) while composing the component grammar — MemeCell demo pile with a match ring + sticker labels + console rows — instead of decoration (criterion 2). The demo-pile lane doubles as the sploot-053 hook: the empty state demonstrates type-words-get-the-picture and offers "upload now" as the direct aha route, so one empty-state design serves both cards as required. Options 4 and 5 survive as noted follow-up layers (status-bar reminder cell; post-first-capture reinforcement) but fail the first-run criterion standalone.
